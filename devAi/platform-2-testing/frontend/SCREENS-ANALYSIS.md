## 1. الشاشة الأولى: دليل وإدارة الشركاء والقطاعات (Partner Directory & Status Matrix)

### الهدف من الشاشة:
تعتبر المدخل التشغيلي الرئيسي لمهندس الفحص والتكامل، حيث تعرض كافة الشركاء الحقيقيين مقسمين بحسب قطاعاتهم (بنوك، تجار، AML) مع مؤشرات حالة الربط الحية، وإحصائيات جاهزية كل شريك.

### عناصر واجهة المستخدم (UI Elements):
* **شريط إحصائيات علوي (Quick KPI Metrics):**
  * إجمالي الشركاء المسجلين.
  * الشركاء المتصلين بالإنتاج (Connected).
  * الشركاء قيد الفحص والاختبار (In-Testing).
  * الشركاء المعلقين (Pending).
* **فلترة وتبويب القطاعات (Sector Filters):**
  * تبويب "جميع الشركاء".
  * تبويب "المؤسسات المالية والبنوك" (Financial Institutions).
  * تبويب "أنظمة التجار ونقاط البيع" (Merchants & POS).
  * تبويب "أنظمة مكافحة غسل الأموال" (AML & Compliance).
* **شبكة بطاقات الشركاء (Partner Cards Grid):**
  * بطاقة كل شريك تحتوي على: الشعار، الاسم، المعرّف (e.g. `ORG_RAJHI_BANK`)، شارة الحالة (متصل/قيد الفحص/معلق)، عدد الـ APIs المخصصة له، ونسبة نجاح الاختبارات.
  * زر إجراء سريع: "فتح كونسول الفحص (Open Test Console)".
* **زر إجراء علوي:** "إضافة شريك جديد (Add Partner Organization)".

## 2. الشاشة الثانية: كونسول تشغيل واختبار الـ APIs (Partner Test Execution Console)

### الهدف من الشاشة:
تتيح لمهندس الفحص اختيار شريك محدد (مثل بنك الراجحي)، واستعراض الـ APIs المخصصة له، وتشغيل حزم الاختبارات الميدانية في بيئات متعددة (Sandbox, Staging, Production)، مع رصد النتيجة اللحظية.

### عناصر واجهة المستخدم (UI Elements):
* **بطاقة الشريك المختار والمعلومات الأساسية (Partner Header Context):**
  * اسم الشريك، المعرّف، البيئة الحالية (محدد خيارات: Sandbox / Staging / Production)، ومفاتيح الربط (API Keys / mTLS status).
* **قائمة الـ APIs المخصصة للشريك (Assigned APIs List):**
  * عرض المسارات المخصصة للبنك (مثل `POST /v1/transfers`، `GET /v1/transfers/{id}/status`).
  * شارة حالة الفحص لكل مسار (Passed 100% / Warning / Failed).
* **لوحة تشغيل الفحص الميداني (Interactive Test Runner Panel):**
  * محدد نوع الطلب والمسار.
  * محرر حمولة الفحص (Request Payload Editor): معبأ بقيم تجريبية قياسية مع إمكانية التعديل.
  * زر تفاعلي رئيسي: **"تشغيل الفحص الآلي (Run Test Execution)"** مع مؤشر تقدم وزمن استجابة (Latency).
  * لوحة النتيجة اللحظية (Response Output Box): تعرض كود الاستجابة (201 Created / 422 Unprocessable Entity) وجسم الاستجابة المنسق.
* **سجل الفحوصات التاريخي للشريك (Audit Test History Table):**
  * جدول يعرض آخر عمليات الفحص التي أجريت مع التوقيت، النتيجة، كود الخطأ، واسم المهندس الفاحص.

## 3. الشاشة الثالثة: مستكشف الشرح والاستعلام المعرفي الفوري (Contextual Spec Inspector)

### الهدف من الشاشة:
حل مشكلة الغموض أثناء الفحص الميداني؛ حيث يمكن للفاحص بنقرة واحدة استدعاء الشرح الرسمي وقوانين العمل وكتالوج الأخطاء المعتمدة في المنصة الأولى دون مغادرة شاشة الاختبارات.

### عناصر واجهة المستخدم (UI Elements):
* **شريط البحث والاستعلام السريع (Quick Spec Search Bar):**
  * إدخال اسم حقل (مثل `idempotencyKey`) أو رمز خطأ (مثل `ERR_LIMIT_EXCEEDED`) أو مسار API.
* **بطاقات الشروحات المستدعاة من المنصة الأولى (Live Spec Cards):**
  * **بطاقة تعريف الحقل ونوعه وقواعده:** نوع الحقل، إلزاميته، نمط الـ Regex، وتصنيفه الأمني المصرفي (PII, PCI-DSS).
  * **بطاقة قوانين العمل المصرفية المعتمدة (Business Rules):** نص الشرط القانوني (مثل `request.amount <= 50000`).
  * **بطاقة كتالوج الأخطاء القياسية:** كود الخطأ، الـ HTTP Status المقابل، ورسالة التوجيه للبنوك.
  * شارة المصدر: "مستخرج ومحدث تلقائياً من المنصة الأولى (Source: Platform 1 Sealed Spec)".

## 4. الشاشة الرابعة: إدارة الأدوار والصلاحيات الديناميكية (Dynamic Access Control & Roles)

### الهدف من الشاشة:
توفير تحكم مطلق واستقلالية تامة للمنصة الثانية، لإنشاء أدوار وظيفية جديدة وتحديد مصفوفة الصلاحيات بدقة متناهية دون كتابة سطر كود واحد.

### عناصر واجهة المستخدم (UI Elements):
* **شريط إدارة الأدوار (Roles Management Bar):**
  * قائمة الأدوار الحالية (مثال: "كبير مهندسي الاختبارات"، "فاحص شركاء ميداني"، "مدقق امتثال خارجي").
  * زر **[إضافة دور جديد +]**: يفتح نافذة لكتابة اسم الدور وتوصيفه.
* **مصفوفة الصلاحيات التفاعلية (Granular Permissions Matrix):**
  * جدول ديناميكي يقسم موارد المنصة الثانية مع مربعات اختيار (Checkboxes):
    * **إدارة الشركاء (Partners):** عرض (View)، إضافة (Create)، تعديل (Edit)، حذف/تجميد (Delete).
    * **تنفيذ الاختبارات (Test Execution):** تشغيل في Sandbox، تشغيل في Production، مسح السجلات القديمة.
    * **اعتماد النتائج (Test Certification):** اعتماد نتيجة الفحص، إصدار تقرير الجاهزية.
    * **الاستعلام المعرفي (Context Query):** استدعاء المواصفات من المنصة الأولى.
* **قائمة المستخدمين المعينين للدور (Assigned Users Panel):**
  * بطاقات موظفي المنصة الثانية المعينين لكل دور، مع زر إضافة مستخدم أو تغيير دوره بضغطة زر.
* **زر الحفظ:** "حفظ وتفعيل صلاحيات الدور (Save Role Permissions)".

## 🔄 مسار حركة مهندس الفحص (Tester User Flow)
```text
[1. دليل الشركاء] 
       ↓ (اختيار شريك مثل: بنك الراجحي)
[2. كونسول الاختبارات] ➔ تشغيل الفحص وملاحظة استجابة الخطأ
       ↓ (حقل أو خطأ غير مفهوم؟)
[3. نافذة الاستعلام الفوري] ➔ سحب الشرح المعتمد من المنصة الأولى وحل المشكلة
       ↓
[4. إدارة الصلاحيات] ➔ تمنح وتضبط وصول المهندسين والمدققين لكل وظيفة
```
